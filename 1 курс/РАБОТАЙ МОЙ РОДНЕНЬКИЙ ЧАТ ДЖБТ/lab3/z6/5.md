# HpcMazeGenerator

Высокопроизводительный генератор идеальных лабиринтов (High-Performance Computing Maze Generator), написанный на C#. Проект реализует оптимизированный итеративный алгоритм Randomized Depth-First Search (Recursive Backtracker) с минимальным потреблением памяти и без рекурсии.

## Описание проекта

Генератор спроектирован для мгновенного создания огромных лабиринтов с использованием техник прямого доступа к памяти (`Unsafe`, `MemoryMarshal`), одномерных массивов и вычислений без ветвлений (branchless programming). 

**Связь с робототехникой и симуляцией:**
Проект идеально подходит для задач процедурной генерации тестовых полигонов в робототехнике и разработке ИИ:
*   **Тестирование алгоритмов навигации:** Мгновенная генерация сложных графов для проверки алгоритмов поиска пути (A*, Dijkstra, D* Lite).
*   **Обучение с подкреплением (RL):** Создание случайных сред (env) для обучения агентов навигации в запутанных пространствах.
*   **SLAM-симуляции:** Генерация карт препятствий (Occupancy Grids) для тестирования алгоритмов одновременной локализации и построения карты.
*   **Стресс-тестирование:** Возможность генерировать сетки размером 10 000 x 10 000 ячеек за миллисекунды для профилирования систем.

## Требования

*   **SDK:** .NET 8.0 или новее.
*   **Зависимости:** Отсутствуют (100% Native C#, без сторонних NuGet-пакетов).
*   **Платформа:** Кроссплатформенный (Windows, Linux, macOS).

## Установка и запуск

1. Создайте новый консольный проект:
```bash
dotnet new console -n MazeApp
cd MazeApp
```

2. Скопируйте исходный код классов (`CellState.cs`, `Maze.cs`, `FastMazeGenerator.cs`) в папку проекта.

3. Обновите `Program.cs` для запуска и соберите проект:
```bash
dotnet build -c Release
dotnet run -c Release
```

## Примеры использования

### Пример 1: Генерация небольшого лабиринта с фиксированным Seed
Использование параметра `seed` позволяет генерировать детерминированные лабиринты, что критически важно для воспроизводимости тестов в робототехнике.

**Код:**
```cs
using System;
using HpcMazeGenerator;

class Program
{
    static void Main()
    {
        var generator = new FastMazeGenerator();
        // Генерация лабиринта 10x5 с seed = 42
        Maze maze = generator.Generate(10, 5, seed: 42);
        
        Console.WriteLine("Сгенерированный лабиринт (10x5):");
        Console.WriteLine(maze.RenderToString());
    }
}
```

**Ожидаемый вывод:**
```text
Сгенерированный лабиринт (10x5):
// Вывод зависит от версии .NET (из-за особенностей реализации System.Random). 
// Здесь будет выведен сгенерированный ASCII-арт лабиринта.
```

### Пример 2: Нагрузочное тестирование (генерация гигантского лабиринта)
Пример демонстрирует скорость работы алгоритма для масштабных симуляций. Метод `RenderToString()` здесь опускается, так как вывод в консоль займет больше времени, чем сама генерация.

**Код:**
```cs
using System;
using System.Diagnostics;
using HpcMazeGenerator;

class Program
{
    static void Main()
    {
        var generator = new FastMazeGenerator();
        int width = 5000;
        int height = 5000;

        Console.WriteLine($"Генерация сетки {width}x{height} ({width * height} ячеек)...");
        
        var sw = Stopwatch.StartNew();
        Maze maze = generator.Generate(width, height);
        sw.Stop();

        Console.WriteLine($"Успешно завершено за {sw.ElapsedMilliseconds} мс.");
    }
}
```

**Ожидаемый вывод:**
```text
Генерация сетки 5000x5000 (25000000 ячеек)...
Успешно завершено за [~150-300] мс. // Время зависит от характеристик CPU (особенно L2/L3 кэша)
```

> **?? Внимание: Large Object Heap (LOH)**
> Для лабиринта 5000x5000 ячеек алгоритм разово аллоцирует два больших массива: `grid` (~100 МБ) и локальный `stack` (~300 МБ). Суммарно около 400 МБ оперативной памяти выделяется напрямую в Large Object Heap. Учитывайте это при интеграции генератора в высоконагруженные серверные или игровые приложения, так как частая генерация гигантских сеток может вызвать ощутимые паузы сборщика мусора (GC).

## Теоретическое обоснование

В основе работы генератора лежит классический алгоритм Randomized Depth-First Search (Recursive Backtracker). Однако стандартная реализация использует стек вызовов (call stack) операционной системы. Для лабиринта размером $W \times H$ глубина рекурсии в худшем случае (длинный змеевидный проход) может достигать $W \times H$. Поскольку размер стека потока в .NET ограничен (по умолчанию около 1.5 МБ), попытка сгенерировать даже лабиринт 150x150 ячеек привела бы к неизбежному `StackOverflowException`. Замена рекурсии на **итеративный подход с явно выделенным массивом-стеком** в куче полностью снимает это аппаратное ограничение, позволяя генерировать сетки из миллионов ячеек.

Наивная реализация графа часто предполагает использование объектов или многомерных массивов флагов (например, `bool[][]`) для хранения состояния проходов (Верх, Низ, Право, Лево) и факта посещения ячейки. В C# один `bool` занимает 1 байт, а многомерные массивы (`[][]`) добавляют огромные накладные расходы на заголовки объектов (минимум 24 байта на каждый вложенный массив). В нашем решении применяется **битовая арифметика**. Состояние каждой ячейки кодируется степенями двойки (1, 2, 4, 8, 16) и упаковывается в единый 32-битный `int`. Это гарантирует строгие 4 байта на ячейку без объектного оверхеда, а чтение/запись проходов выполняется мгновенными операциями `|` и `&`.

Наконец, ключевую роль в производительности играет **кэш-локальность (cache-friendly layout)**. Современные процессоры считывают оперативную память не побайтово, а блоками (cache lines, обычно по 64 байта). Использование `int[,]` или `int[][]` приводит к фрагментации данных в куче и постоянным промахам процессорного кэша (cache misses). «Сплющивание» двумерной сетки в одномерный массив `int[] Grid` обеспечивает последовательное расположение данных в памяти. Аппаратный префетчер (prefetcher) процессора легко предсказывает такой паттерн доступа, заблаговременно подгружая соседние ячейки в быстрые кэши L1/L2, что максимизирует пропускную способность памяти при обходе графа.

## Структура проекта и архитектура

Архитектура построена вокруг концепции **Data-Oriented Design (DOD)** для максимальной утилизации процессорного кэша (L1/L2).

*   **`CellState` (Enum):** 
    Битовые флаги (North, East, South, West, Visited). Хранение состояния в виде битовых масок позволяет выполнять проверки и мутации за `O(1)` с использованием побитовых операций (`|`, `&`), исключая ветвления.
    
*   **`Maze` (Struct):** 
    `readonly struct`, выступающая легковесным контейнером данных. Двумерная сетка эмулируется через одномерный массив `int[] Grid`. Это гарантирует последовательное расположение данных в памяти (Cache Locality). Содержит метод `RenderToString()` для визуализации.

*   **`FastMazeGenerator` (Class):**
    Ядро системы. Основные архитектурные решения:
    *   **Отсутствие рекурсии:** Стек вызовов заменен локальным плоским массивом `int[] stack`, размер которого аллоцируется заранее. Это полностью исключает `StackOverflowException`.
    *   **Ref-локальные переменные:** Использование `MemoryMarshal.GetArrayDataReference` и `Unsafe.Add` обходит встроенные в .NET проверки границ массивов (bounds checking) в горячем цикле.
    *   **Branchless Out-of-Bounds:** Проверка выхода за границы сетки реализована через побитовые сдвиги (`>> 31`), что предотвращает сброс конвейера процессора (pipeline flush) из-за неверных предсказаний переходов.
    *   **Предвычисление:** Статический конструктор предвычисляет 24 возможные перестановки из 4 направлений (сохраненные в плоский массив из 96 элементов), избавляя алгоритм от необходимости выполнять случайную сортировку (shuffle) во время работы.
